# タスクリア — 「今日のひとつ」MVP v1.1

積読・積みゲー・積みプラを「管理して終わり」にせず、**今日楽しむものを選び、少し遊び、記録を残す**ローカル保存型Webアプリです。

## 起動

`index.html` をChromeなどのブラウザで開くだけです。パッケージのインストール、ビルド、外部API、アカウントは不要。静的サイトとして配置できます。GitHubに上げる場合、`index.html`、`style.css`、`script.js` は同一階層に置いてください。

## 体験の中心

1. 本・ゲーム・プラモデルなど、あとで楽しみたいものを登録します。
2. 「今日のひとつ」から始めます。合わなければ別の候補に切り替えられます。
3. 途中でやめてもよいので、5・15・30・60分、または入力した時間を「楽しんだ記録」に残せます。記録は**自己申告**であり、タイマーではありません。
4. 次にやりたいこと、短いメモ、今週の合計、過去の記録から再開できます。完了したときだけ「完了」を選びます。

## v1.1の機能

- アイテムの登録・編集・削除、カテゴリ、状態、購入日、メモ、次にやりたいこと
- 今日のひとつの切り替えと、開始・時間記録・任意の完了
- 趣味ログ（日付、作品名、1〜600分、メモ）、週合計、作品別累計、履歴の追加表示・個別削除
- 名前・メモ・次の行動からの検索、カテゴリ/状態フィルタ、登録順/作品名順
- JSONで全データの書き出し・復元。積みアイテムを削除しても趣味ログは保持
- 長文・ゼロ件・検索0件・320px幅でのレイアウト対応、ユーザー入力のテキスト表示時に`textContent`を使用
- 他タブとの競合書き込み検知、異常なデータ・容量不足時の上書き防止。読めない元データの退避と明示的なバックアップ復元

## 保存と互換性

- 保存先は`localStorage`のキー `taskclear-mvp-v1` を維持し、読み込み時にv1のデータをv2構造へ正規化します。上書きは**次の保存操作時**のみです。
- さらに旧 `hobbyBacklogItems` があり新キーがない場合、新キーへ**コピー**して移行します。元の旧データは削除しません。
- 旧版に画像のファイル名しか保存されていないため、画像の実体は引き継げません。v1.1でも画像保存は対象外です。
- バックアップはJSON形式。アイテム上限2000件、趣味ログ上限5000件。読み込みファイルは8MBまで。壊れたJSON、未知のバージョン、不正なログは拒否します。
- 読み込みに失敗した場合は、既存データを編集せず、原本テキストの退避とバックアップ復元への入口を表示します。復元は上書きの事前確認が必要です。
- 複数タブから同時に編集した場合、保存前にストレージの内容を比較して古い状態による上書きを拒否します。最新データを再読込してください。
- ログは端末の現在の月曜日から今日までを「今週」として集計します。未来のログを手入力することはできません。

**重要**：別端末への自動同期はありません。ブラウザデータの削除で消失し得るため、時々JSONを保存してください。

## 今回入れなかったもの

通知・カレンダー同期・課金・SNS共有・PWAオフラインキャッシュ・アカウント・画像の実体保存・自動タイマーは、利用状況が分かるまで追加しません。

## テスト

```bash
node --check script.js
node tests/smoke-test.cjs
```

実ChromiumのDOM描画・操作の確認は任意で：

```bash
python tests/browser_test.py
```

このブラウザ確認用スクリプトでは、環境のURLアクセス制限を回避するためCSS/JSをHTMLへインライン化し、`localStorage`をテスト用に模擬しています。**実ブラウザでのネイティブlocalStorage永続化・デプロイ先でのネットワーク挙動・Android実機**を保証するものではありません。これらは公開前に別途確認してください。ブラウザテストに使用するPlaywrightとChromiumは別途必要です（製品本体には不要）。

## 手動確認（公開前）

1. 空の新規環境で2件登録し、今日の候補切替→開始→時間記録→完了を確認
2. ページを再読み込みし、作品・今週の時間・履歴が維持されることを確認
3. 作品の編集・削除後も過去のログが残ることを確認
4. JSON書き出し→データ変更→JSON復元で元に戻ることを確認
5. 旧版 `hobbyBacklogItems` と v1 `taskclear-mvp-v1` の移行を確認
6. スマホ実機でダイアログ・文字入力・ファイル復元・最小幅を確認
7. 2タブで同時に編集して競合上書きが防止されることを確認

## 方針

情報の優先度は「今日のひとつ → 楽しんだ記録 → コレクション → データ管理」の順です。モチベーションを罪悪感や課金圧で作るのではなく、小さく始める実用性を検証します。Draft PRの段階では本番サイトに自動反映せず、テスト完了後にマージを判断します。
