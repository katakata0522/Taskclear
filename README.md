# タスクリア — 趣味バックログ MVP

積読・積みゲー・積みプラの「次に楽しむ1件」を決める、ローカル保存型Webアプリ。

## 起動

`index.html` をブラウザで開くだけです。依存関係・アカウント・API・ビルド工程はありません。静的ホスティングに配置できます。

## MVPの範囲

- 本 / ゲーム / プラモデル / その他の登録、編集、削除
- 未着手 / 進行中 / 一時中断 / 完了の管理
- 今日楽しむ1件の表示、別の候補の選択、開始/完了アクション
- 名前・メモ検索、カテゴリ/状態フィルタ、登録順/作品名順
- `localStorage` 保存、JSONバックアップ/復元
- スマホ対応、ゼロ件/検索ゼロ件の画面、長文折返し、テキスト出力時のXSS対策

## 旧データの扱い

旧 `hobbyBacklogItems` があり、新キー `taskclear-mvp-v1` がない場合のみ移行します。旧データは**削除せず**残します。旧版で選択した画像はファイル名しか保存されていないため、MVPに画像表示はありません。新バージョンへ安全に移行するため、購入日・メモ・状態は保持します。

## 制限 / 注意

- 別端末には自動同期されません。ブラウザデータを削除すると消えるのでJSONを保管してください。
- 通知、カレンダー、課金、共有、画像実体保存、複数アカウントは対象外です。
- JSONの読み込みは現在のデータと**置き換え**です。確認ダイアログを表示します。
- JSONは2000件/8MBまで。破損データの自動修復はしません。元データを勝手に上書きしない設計です。
- 実利用者へのテスト・公開ドメインへのデプロイは未実施です。

## 手動スモークテスト

1. 新規データゼロ件で追加→一覧・今日の1件・件数が更新される。
2. 2件登録→「別の候補」→開始→完了→件数・候補が更新される。
3. 編集、検索、カテゴリ/状態フィルタ、削除が働く。
4. ページ再読込後も内容が維持される。
5. JSON書き出し→編集→読み込み→元データに戻る。
6. 旧 `hobbyBacklogItems` を設定して起動し、移行先・旧データが両方あることを確認。

## 実装方針

HTML / CSS / JavaScriptのみ。外部通信ゼロ。UIは「今日の1件 → 手元の積み一覧 → データ管理」の順に情報量を落としています。

## ローカル検証

```bash
node --check script.js
node tests/smoke-test.cjs
```

自動テストはDOM模擬環境での機能検証です。実ブラウザ/モバイルでの最終確認は公開前に別途行います。
